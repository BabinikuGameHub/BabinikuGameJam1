## 게임 소개

48시간 안에 "굴러가는" 탑다운 슈터를 만드는 것이 잼의 목표였습니다. 전투는 **손전등 던지기 → 불렛 타임 진입 → 조준 → 사격**으로 이어지는 4단계 루프로 설계했습니다.

## 핵심 구현

### 전투 상태 머신

전투 루프(손전등 투척 → 불렛 타임 → 조준 → 사격)를 상태 머신으로 구현했습니다. 짧은 개발 기간 안에서 가장 신경 쓴 부분은 **중간 취소 처리**였습니다. 플레이어가 시퀀스 도중 다른 입력을 넣거나 상황이 바뀌어도 각 단계가 빠짐없이 취소·복귀되도록 상태 전이를 짰습니다. 상태가 꼬인 채로 남는(예: 불렛 타임에 걸린 채 못 빠져나오는) 케이스를 만들지 않는 것이 목표였습니다.

### 데이터 기반 적 설계 (ScriptableObject)

적 스테이터스는 ScriptableObject 에셋으로 분리했습니다. 코드를 건드리지 않고 데이터 에셋만 추가/수정해서 적 밸런스를 조정할 수 있는 구조입니다.

### 비프로그래머용 레벨 디자인 (60×40 타일그리드)

맵을 60×40 타일그리드로 구성해, 프로그래머가 아닌 팀원도 코드를 몰라도 스테이지를 직접 배치할 수 있게 했습니다. 48시간이라는 제약 안에서 병렬 작업(레벨 디자인과 시스템 구현을 동시에 진행)을 가능하게 만든 선택이었습니다.

### QA

마감 직전 QA 사이클에서 진행 불가(soft-lock) 버그 두 건을 찾아 출시 전에 수정했습니다.
